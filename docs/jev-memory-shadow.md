# NyoruMemory Jev 기억 유용성 관찰 실험

0.28.0부터 통합 설치 파일에 포함됩니다. 최초 개발 브랜치는 `codex/jev-memory-shadow`, 기반 버전은 0.27.2입니다.

사용자가 제공한 NyoruRPG 계획서를 NyoruMemory에 적용한 선택형 관찰 실험이다. 관찰에서 고른 가상 기억을 실제 검색 결과 대신 주입하지 않는다. 기존 기록 분석에서는 실제 답변 연결을 확인하지 못했으며, 이번 배포 통합이 답변 연결이나 효과를 입증하는 것은 아니다.

## 사용 위치

1. 통합 설치 파일: [NyoruMemory.js](../NyoruMemory.js). 로컬 프로젝트에서는 `release/NyoruMemory.js`.
2. **모델 및 설정 → JEV 선택 도우미 → 기억 유용성 관찰 · 실험**을 켜고 저장한다. 기본값은 꺼짐이다. 기존 JEV 주소·모델 ID·키를 사용한다. 다른 네 가지 JEV 도우미는 켜지 않아도 된다.
3. 실제 `[NyoruMemory.memory]` 또는 `[NyoruMemory.recent]` 슬롯을 사용하는 답변부터 관찰한다. 미리보기는 기록하지 않는다.
4. **플레이 중 Jev 효과 자동 비교**를 켜고 저장하면 관찰도 함께 켜진다. 비교 기능의 기본값은 꺼짐이다. 별도 검수 모델이 켜져 있으면 그 모델, 아니면 기억 정리 모델이 독립 평가와 답변 평가를 자동 수행한다. 생성당 기존 Jev 호출 외에 평가 모델을 최대 2회 호출하며 비용이 발생한다.
5. **Jev 효과 · 자동 비교 기록**에서 필요한 기억 비율, 중요 기억 누락, 불필요한 토큰, 같은 설정의 누적 결과, 실제 답변 활용 근거와 요청/응답을 본다. 기록 변경을 구독하여 화면을 갱신한다. 수동 점수 입력은 필요 없다.
6. **직접 평가 · 이전 관찰 기록**에는 기존 수동 평가 버튼이 남아 있다. 창을 닫으면 수동 평가만 중단하며, 자동 비교는 계속한다. 설정 변경·기억 삭제·플러그인 종료 시 해당 자동 작업을 취소한다.

통합 파일은 기존 플러그인과 동일한 내부 이름 `longmemory`를 유지한다. 기존 기억과 관찰 설정·기록을 이어 쓰는 교체용이며 같은 이름의 두 플러그인을 동시에 실행하는 용도가 아니다. 기존 업데이트 주소와 안내 기능을 사용하고, 설치는 사용자가 선택한다. 별도 `--experimental` 빌드는 개발용이며 배포 경로가 아니다.

## 관찰 범위

`retrieve()`의 기존 후보 선택·가중치·토큰 한도 조정이 모두 끝난 뒤 결과를 읽는다. 실제 슬롯 구성에 따라 전송된 recent/retrieved 항목을 기록한다. 자동 비교가 켜지면 동일 검색에서 나온 탈락 후보도 최대 40개 후보 안에 포함한다. 최근 기억 우선 포함과 관련성 검색 선택을 구분한다. Jev의 가상 선택 결과는 실험 로그에만 저장하며 실제 주입은 기존 검색 결과를 사용한다.

## 플레이 중 자동 비교 (2026-10-11)

- 기준 방식은 해당 생성에 실제 주입한 기억 ID 전체다. 비교 후보는 이미 계산한 검색 순위·단어 점수에서 고른 최대 40개다. 탈락 후보가 있으면 실제 선택에서 최대 24개를 우선 가져와 탈락 후보를 평가할 자리를 남긴다. 추가 임베딩 요청이나 재검색은 없다.
- 비교 후보 밖의 기존 기억, 최근 우선 기억, 공식 수정은 양쪽에서 유지한다. 미평가·실패·판단 보류도 기존 포함 여부를 유지한다. 전체 보관함을 Jev가 평가했다고 표시하지 않는다.
- 자동 비교에서는 Jev에 다음 답변의 유용성 질문 하나만 기억 조각마다 보낸다. 중요 → 도움 순서로 가상 선택하고, 완전한 기록의 모든 조각이 불필요라고 판단된 경우 가상 선택에서 제외한다. 조각 하나라도 판단 보류·누락이면 기존 상태를 유지한다. 낮은 확신도도 결과에 남기며 자동으로 실제 기억을 제거하지 않는다.
- 같은 주입 용량과 같은 렌더링 규칙을 적용한다. 이미 계산한 기억별 토큰을 재사용하고 최종 문자열의 토큰을 확인한다. 토큰 계산은 내장 추정치이며 제공자의 과금 토큰과 다를 수 있다.
- 독립 평가에는 같은 40개 이하 후보와 제한된 최근 대화만 보낸다. 평가용 ID와 순서는 따로 구성하고, 모델 이름·검색 순위·포함 여부·Jev 판단·실제 다음 답변은 숨긴다. 원문 언어는 유지한다.
- 독립 평가 입력은 후보 발췌 합계 약 18,000자 / 자료 JSON 48,000바이트 이내다. 잘린 부분은 표시한다. 답변 평가도 48,000바이트 이내이며 답변 전문을 자르지 않고, 한도를 넘으면 생략 이유를 기록한다. 평가 출력은 최대 8,192토큰, 제한 시간은 60초 또는 사용자가 설정한 더 작은 값이다.
- 독립 평가 1회, 정확히 연결된 답변의 활용 평가 1회로 생성당 최대 2회 추가 호출한다. 작업은 배경 직렬 큐, 대기 포함 최대 3개다. 실패한 유료 요청은 자동 반복하지 않는다. 같은 입력의 중복 기록은 누적 평균에서 한 번만 센다.
- 사용자가 자동 비교와 이중 임베딩 자동 비교를 모두 켜면 각 기능의 평가 비용이 따로 발생한다.

### 지표의 범위

| 지표 | 계산과 한계 |
| --- | --- |
| 선택한 기억 중 유용한 비율 | 독립 AI가 중요/도움으로 판단한 선택 기억 / 판단이 나온 선택 기억. 미평가·불확실 제외, 분모 표시 |
| 후보에서 유용한 기억을 찾은 비율 | 선택한 유용 기억 / 비교 후보 안에서 독립 AI가 유용하다고 판단한 기억. 전체 보관함 회수율 아님 |
| 중요 기억 누락 | 후보 안에서 중요로 판단했으나 선택되지 않은 기억. Jev가 기존에 포함된 중요 기억을 제외한 건수도 별도 표시 |
| 불필요한 토큰 | 비교 후보 안에서 불필요로 판단된 선택 기억의 토큰 추정 합. 최근/고정 기억도 포함 여부에 따라 반영 |
| 전체 주입 토큰 차이 | 같은 형식으로 렌더링한 기존 선택과 가상 Jev 선택의 차이. 후보 밖 기존 기억은 양쪽 고정 |
| 실제 답변 활용·충돌 | 저장된 답변과 기억의 인용을 확인한 AI 판단. 비언급을 모순으로 간주하지 않음. 인과적 개선율 아님 |
| 비용과 시간 | Jev·독립 평가·답변 평가별 실제 API 요청 수, 보고 input/output usage, 호출 시간. 미보고는 0이 아님 |

누적 평균에는 같은 검색/모델/평가/용량/기준 설정에서 모든 후보의 Jev 판단과 독립 판단이 유효한 생성만 포함한다. 불확실·부분 실패·중복은 건수와 개별 지표를 남기고 평균에서 제외한다. 낮은 확신도 자체는 제외 사유가 아니다. 확신도 0–0.5 / 0.5–0.85 / 0.85–1 구간별 독립 평가 일치율을 함께 보여준다. 이는 모델의 판단 확신도와 독립 AI의 일치이며 실제 정답률이 아니다.

실제 메인 답변은 한 번만 생성한다. Jev 방식의 별도 답변을 생성하는 유료 A/B 실험은 이 기능에 포함하지 않는다. 따라서 ‘Jev가 있었을 때 실제 답변이 더 좋아졌음’을 인과적으로 입증했다고 표시하지 않는다. 로그는 이후 동일 자료로 비교할 수 있도록 생성 시점 ID·revision·원문 해시·후보·선택·근거를 보존한다.

관찰 지점은 **우리 플러그인의 주입 직후**다. 뒤에서 실행되는 다른 플러그인이 프롬프트를 바꿀 수 있으므로 공급자에 도착한 최종 네트워크 본문이라고 주장하지 않는다. `injectedSegments`는 각 슬롯의 정확한 삽입 문자열·원래 메시지 위치를 기록하고, `injectedText`는 함께 보기용이다. `selectionOrder`는 선택 결과 배열 순서이며 렌더러가 종류별로 배치한 최종 문장 위치와 구별한다.

이 프로젝트의 검색 단위는 추출 원문 청크 자체가 아니라 내용·대사, 사실, 관계, 줄거리 등의 **기억 레코드**다. 로그의 `recordId`/`id`는 이 기억 ID이고 `sourceChunkId`는 원문 청크와 연결 가능한 경우의 참조다. ID가 없는 원문을 만들어내지 않는다. 원래 기억 레코드, 검색용 텍스트, 실제 주입 표시문을 함께 남긴다.

별도의 전체 캐릭터 상태/로어북을 조회해 섞지 않는다. 당시 실제 선택된 사실·관계가 있으면 그 텍스트와 제한된 최근 대화가 판단 자료가 된다. 전체 대화나 다른 프롬프트 영역을 읽은 것처럼 평가하지 않는다. `query`에는 실제 검색 질의를 보존하고, Jev에게는 제한된 `recentContext`만 보낸다.

기록 항목:

- 내부 생성 관찰 UUID, 실제 캐릭터/채팅 ID, 기록 시각, 기억 revision, 원문 스냅샷 해시와 메시지 ID/해시 목록.
- 실제 질의·선택된 기억·주입문, composite 검색 순위, semantic/keyword/recency/최종 점수. semantic이 null이면 임베딩 점수를 받지 못한 것이다.
- 영어 질문·기준 버전과 원래 언어의 state, 실제 요청/응답, 모델명, 서버 반환 모델명, HTTP 상태, latency, usage, 실패·생략 사유.
- 선택 확률·확신도, 의미 관련성 Score, 서사 유용성 Choice, 시점 적용 여부 Choice, 중복 Noul 확률.
- 답변 연결 상태·메시지 ID·정확한 답변 본문·관측 시각, 독립/답변 활용 평가, 비교 결과.

요청은 배경에서 직렬로 진행하며 메인 요청 훅은 평가를 기다리지 않는다. 관찰 작업은 동시에 하나만 실행한다. Jev 실패 쿨다운과 캐시는 기존 JEV 도우미와 공유하지 않고, 관찰에서는 결과 캐시를 사용하지 않는다. CPU·네트워크·디스크 자원 사용까지 0이 되는 것은 아니며 실사용 성능은 미확인이다.

## 질문과 입력 한도

Jev 질문/선택 기준은 영어, 대화·기억 state는 원래 문자열 그대로 보낸다. 번역·요약하지 않는다. 공식 API는 혼합 Choice/Score/Noul과 질문 ID별 응답을 제공한다. Score는 정수 선택이 아니라 분포의 기댓값이며 Noul은 yes 확률이다. Noul에 별도 confidence를 만들어 붙이지 않는다.

- 기본 관찰 최근 대화 3,000자, 조절 500~5,000자. 마지막 메시지부터 잘라 원본 ID와 UTF-16 위치를 남긴다.
- 기본 한 답변 최대 8회, 조절 1~32회. 사후 평가도 생성 당시 저장한 호출 한도를 각 단계에 사용한다.
- 기억이 길면 최대 10,000 UTF-8 바이트 조각으로 나누고 원문 전문과 조각 위치를 모두 남긴다. 서로게이트 쌍은 나누지 않는다.
- 기존 `fitsJev`의 보수적인 애플리케이션 한도(질문 최대 60개, 묶음 60,000바이트, state+개별 질문 30,000바이트)를 재사용한다. 이는 공급자의 문맥 토큰 한도를 보장하거나 모델 최대치를 뜻하지 않는다. 사용자 제공 수십만 토큰 예시를 상수로 넣지 않았다.
- 호출 한도·입력 한도·이전 요청 진행·취소·채팅 변경·API 실패는 명시적으로 기록한다. 평가하지 않은 항목에 정상 점수를 붙이지 않는다.
- 중복 판단은 해당 묶음과 최근 대화 범위다. 전체 보관함 중복 판정이 아니다.

## 답변 연결의 한계

현재 연결한 RisuAI 훅에는 확실한 생성 요청 ID와 취소 통지가 없다. 내부 UUID를 호스트 ID라고 부르지 않는다.

`afterRequest`에서 받은 본문이 저장된 캐릭터 메시지와 정확히 같고, 이전 메시지 ID·본문이 그대로인 단일 요청만 연결한다. output 이벤트가 응답보다 먼저 오면 보관한 뒤 응답 도착 시 다시 연결한다. 저장 훅 누락·지연에 대비해 응답 뒤 0.25/1/2.5/6/15초에 읽기 전용으로 해당 채팅을 확인하며, 연결되면 이후 확인을 생략한다. 새 메시지 추가와 마지막 캐릭터 답변 재생성을 구분한다. 다른 플러그인이 본문을 바꾸거나 요청이 겹치면 ‘연결 미확인’으로 남긴다. 이미 응답을 받은 과거 미연결 기록 때문에 다음 요청까지 계속 겹침으로 분류하지 않는다. 5분 내 연결이 없으면 답변 평가를 생략하고 이유를 남긴다.

Jev 수신 시각과 메인 답변 수신 시각을 따로 저장한다. 정확히 연결된 답변의 수신 이전/이후 결과를 분리하고 수신 시각을 모르면 미확인으로 둔다. 수신 이전 완료가 토큰 생성 시작 이전이었다는 뜻은 아니다. Jev에는 실제 다음 답변을 보내지 않으며 늦게 온 Jev 결과로 메인 답변을 바꾸지 않는다.

## 수동 사후 평가

1. 독립 평가: 당시 한정된 최근 대화와 선택 기억만 보낸다. Jev 결과·점수·선택 이유·실제 다음 답변은 포함하지 않는다.
2. 답변 활용 평가: 같은 기록에서 독립 평가를 마친 항목과 정확히 연결된 답변을 사용한다. Jev 결과와 독립 평가 결론은 보내지 않는다. 실제 사용 여부와 ‘말로 사용하지 않았어도 연속성에 필요했는지’를 구분한다.

사후 평가 요청은 메인 모델과 별도인 기존 플러그인 생성 API를 재사용한다. 감사를 위해 PDF 대신 텍스트 요청을 보낸다. 연결된 답변까지 포함한 자료가 48,000바이트를 넘으면 답변을 몰래 잘라 평가하지 않고 해당 묶음을 생략한다. 빈 응답·JSON 오류는 자동 재구축이나 무한 재시도 없이 실패로 기록한다. 부분 성공은 보존한다. 독립 평가를 다시 실행하면 이전 답변 활용 평가는 무효화한다.

근거는 원문에 실제로 존재하는 짧은 인용만 허용한다. 식별자 일치·중복·JSON 문법·범위는 코드로 확인한다. 검수 AI의 판단은 객관적인 정답이나 인과관계 증명이 아니다.

수동 비교에서는 조각난 기억, 불확실, 미평가를 제외한다. 낮은 확신도도 전체 비교에 포함하고 0.85 이상 결과를 따로 표시한다. 분류 일치율, 중요 기억 누락률, 불필요 기억의 중요 오판 비율, 답변 활용 비율과 각각의 분모를 기록한다. 답변 수신 전 평가만의 집계를 별도로 제공한다. 0건은 0% 대신 자료 없음이다. 독립 AI 판단과의 일치이지 기억 개선 효과나 절대 정확도가 아니다.

## 저장·내보내기

현재 기기 저장소 어댑터를 재사용하되 `@nyoru-shadow-v1:`으로 구분한 별도 아카이브 그룹에 기록한다. 일반 기억의 저장 대기열·revision·원문을 변경하지 않는다. 채팅별 최근 64회 / 16MiB, 오래된 기록부터 제외한다. 긴 문자열은 내용 해시를 참조하여 중복 저장을 줄인다. 별도의 전체 기억 사본은 만들지 않는다.

실험 설정 4개(`jevShadow`, `jevShadowCompare`, `jevShadowContextChars`, `jevShadowMaxCalls`)는 `longmemory:v1:shadow-settings`에 보관한다. 정식 0.27.2의 엄격한 설정 스키마에 알 수 없는 키를 넣지 않는다. 기존 저장된 자동 비교 설정이 없는 경우 OFF다. 새 내보내기 형식은 `nyorumemory-shadow-v2`이며 이전 관찰 기록도 계속 읽는다.

내보내기는 인증정보를 가린 원문·선택 기억·주입문·요청/응답·연결된 답변을 포함한다. 해시 참조는 해제하여 외부에서 그대로 재분석할 수 있다. 사용량 미보고는 null, 요금은 추정하지 않는다. 기록 내보내기는 기억 백업과 별개이며 로그를 기억으로 복원/적용하지 않는다. 실험 기록 저장이 실패하면 관찰 경고를 남기고 기존 기억 처리는 계속한다.

## 구현 파일

- `retrieval.js`: 최종 선택 후 선택적 관찰 정보.
- `main.js`: 수신/주입/출력 훅 연결, 실험 설정 분리.
- `memory-shadow.js`: 관찰 생명주기, 분할, 보수적인 답변 연결, 수동 평가, 지표.
- `shadow-criteria.js`: 영어 Jev 질문과 독립/활용 평가 지침.
- `shadow-log.js`: 기존 저장소·인증정보 가리기 재사용, 독립 아카이브, 용량 제한·중복 문자열 참조.
- `shadow-ui.js`: 기록·근거·실제 요청·사용량·비교·내보내기.
- `jev-comparison.js`: 동일 검색의 비교 후보, 같은 용량의 가상 선택, 누락·토큰·확신도별·누적 지표.
- `shadow-evaluation.js`: 독립/답변 자동 평가 입력, 부분 응답 보존, 근거 인용 확인, 보고 usage 집계.
- `jev.js`: 관찰 인스턴스에서만 Score/Noul 응답 검사를 선택적으로 활성화.
- `tools/build.mjs --experimental`: 실험 파일만 생성, 정식 파일/업데이트 목록 미변경.

## 실행하지 않은 작업

사용자의 테스트 금지 지시에 따라 테스트 작성·실행, 정적 검사 명령, 앱/플러그인/브라우저 테스트, 연결 테스트, 유료 API 호출, 실제 대화 실험을 하지 않았다. 설치용 JS를 묶는 빌드만 수행한다. 실제 호스트 이벤트 순서, 한국어 기억 판단 품질, 실사용 지연·메모리 영향은 미확인이다. 실험 기록이 모이기 전에는 Jev가 도움이 됐다는 결론을 내릴 수 없다.
