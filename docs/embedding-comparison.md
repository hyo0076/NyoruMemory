# 임베딩 하나와 둘 비교

2026-10-10 · 로컬 실험 브랜치

## 플레이 중 자동 기록과 AI 평가

모델 및 설정 → 임베딩 연결에서 **플레이 중 자동 비교 · AI 평가**를 켜고 저장한다. 또는 **자동 비교 기록 보기 → 설정 저장하고 자동 비교 켜기**를 사용한다. 두 임베딩 연결이 필요하다. 별도 평가 비용이 있으므로 기본값은 꺼짐이다.

실제 메인 요청의 기억 슬롯에 기억을 주입했을 때 자동으로 기록한다. 사용자가 검색 문장을 입력하거나 기억마다 점수를 매길 필요가 없다. 최신 대화는 과거 기억을 찾는 검색 기준이며, 이 비교 때문에 다시 요약하거나 저장하지 않는다. 기본 검색 기준은 마지막 메시지 2개이고, 기존 ‘참고할 최근 대화’ 설정을 따른다.

- 실제 검색에서 이미 계산한 첫 모델·둘째 모델·RRF 상위 10개를 재사용한다. 기록을 위한 추가 임베딩 호출이나 세 번의 재검색은 없다.
- 모델별 순위, 원래 유사도, 검색 시간, API 호출량, 보고 사용량, 캐시 여부와 실제 주입 ID를 보관한다. 단독 모델을 사용했을 때의 주입을 별도로 실행하지 않는다.
- 세 결과의 합집합(최대 30개)을 한 번만 평가한다. 검수 모델을 별도로 연결했다면 그 모델, 아니면 기억 정리 모델을 사용한다. Jev 관찰 기능과는 별개다.
- 평가자는 어느 임베딩이 찾았는지, 순위나 점수가 얼마인지 보지 않는다. 현재 장면에 필요한지와 짧은 사유만 반환한다. 기억·검색 순위·메인 답변은 수정하지 않는다.
- 메인 요청은 평가 완료를 기다리지 않는다. 뒤에서 평가 API를 최대 1회 호출하며 실패 시 유료 재시도를 반복하지 않는다. 같은 채팅에서 동일 평가 자료와 모델 설정이면 이번 실행의 이전 판단을 재사용한다.
- 평가 입력은 최근 대화 마지막 3,000자와 후보 발췌다. 후보 텍스트 합계는 최대 약 18,000자, JSON 자료는 40,000바이트 이하로 줄인다. 잘린 자료는 표시하고 판단 보류를 허용한다. 전체 대화·보관함을 다시 읽지 않는다. 평가 호출은 최대 출력 4,096토큰, 시간 60초 이내이며 기존 모델 설정이 더 작으면 그 한도를 따른다.
- 일부 검색 실패, 실제 주입 없음, 최근 기억 슬롯만 사용, 평가 대기 누적, 모델 미설정은 기록에 생략 사유를 남긴다. 원문 연결 표시나 기억 슬롯을 받지 못한 경우에는 최근 수신 상태에 원인을 표시한다.

**자동 비교 기록 보기**에 AI 판단과 누적 비교가 표시된다. ‘필요’와 ‘도움이 됨’을 유용한 기억으로 세며 ‘판단 보류’를 불필요로 계산하지 않는다. 세 방식의 상위 후보를 모두 판단한 기록만 평균에 포함한다. 같은 자료를 재평가 없이 재사용한 기록은 평균에서 중복 집계하지 않는다. 평가 모델·기준과 수동 판단이 다른 기록도 섞지 않는다.

이 값은 AI가 추정한 검색 후보의 유용성이다. 전체 보관함의 정답 회수율이나 실제 RP 답변 품질 개선율은 아니다. API 평가 요청·응답과 usage를 함께 내보낼 수 있고, 미보고 사용량은 0으로 취급하지 않는다.

자동 기록은 기존 수동 기록을 보존하며 같은 채팅의 최근 24회 / 8MiB 한도를 사용한다. 로컬 저장소는 변경된 기록만 갱신한다. 창을 닫아도 자동 평가는 계속되며, 설정을 끄거나 기억을 모두 삭제하거나 플러그인을 종료하면 중단한다. 삭제된 기록은 늦게 온 응답으로 되살리지 않는다. 이전 실행의 미완료 평가는 완료 미확인으로 표시하고 자동 재호출하지 않는다.

## 수동 비교 · 선택 사항

1. 모델 및 설정의 임베딩 연결에서 두 서비스를 설정한다.
2. **자동 비교 기록 보기 → 직접 비교 도구 → 수동 비교 도구 열기**를 연다. 최근 대화가 검색 문장에 들어 있으며 직접 바꿀 수 있다.
3. **두 모델로 비교하기**를 누른다. 현재 입력된 연결을 사용하고 저장된 검색 설정은 바꾸지 않는다. 버튼 실행에는 임베딩 API 비용이 발생할 수 있다.
4. 첫 번째만, 두 번째만, 두 결과를 RRF로 합친 순위를 나란히 비교한다. 찾아온 기억에 필요·불필요를 표시하면 품질 지표가 계산된다.
5. 세 방식 모두 놓친 필요 기억은 이번 비교에 사용한 기억 전체에서 글자로 찾아 추가한다. 이 검색과 평가는 로컬 계산이며 AI를 호출하지 않는다.

두 모델의 검색은 한 번씩 수행한다. 긴 기억은 기존 배치 규칙에 따라 여러 요청이 필요할 수 있다. 각 모델의 결과를 재사용하므로 세 비교 열 때문에 같은 검색을 세 번 호출하지 않는다. 기존 벡터와 검색 문장 캐시를 재사용한다. 후보 주입 결과도 이미 계산한 점수로 생산 코드의 단어 검색·최근 기억 우선·이름·용량 제한을 그대로 적용한다. 메인 RP 답변이나 검수 AI는 호출하지 않는다.

## 수동 비교 지표를 읽는 법

- **임베딩 검색 시간:** 두 모델을 동시에 실행한 이번 작업에서 각 연결이 끝나기까지의 시간이다. 단독 모델을 별도 환경에서 실행한 속도와 같다고 해석하지 않는다. 큐 대기·캐시 읽기·색인·벡터 비교를 포함하고, 이후 세 가지 주입 후보 계산은 제외한다.
- **실제 API 요청:** 네트워크로 보낸 요청 수다. API 응답이 실패해도 보낸 요청은 센다.
- **API 보고 사용량:** 제공자가 응답에 보고한 토큰 수다. 사용량을 보고하지 않은 호출은 미보고로 표시한다. 일부만 보고한 경우 알려진 합계와 미보고 호출 수를 함께 표시한다. 요금은 추산하지 않는다.
- **캐시 / 새로 임베딩한 조각:** 초기 색인을 포함한 호출인지, 새 대화 검색만 하는 호출인지 구분한다. API가 0회라면 캐시를 이용한 실행이며 API 속도를 측정한 것이 아니다.
- **상위 결과 중 필요한 비율:** 각 방식의 상위 K개를 모두 평가한 경우에만 필요 개수 / 실제 반환 개수를 표시한다. 미평가를 불필요로 간주하지 않는다.
- **표시한 필요 기억 회수율:** 사용자가 필요하다고 표시한 기억 중 상위 K개에 포함된 비율이다. 전체 보관함의 완전한 정답 집합이 아니며, 선택된 후보만 평가하면 편향될 수 있다. 놓친 기억 추가 기능으로 알려진 누락도 포함할 수 있다.
- **주입 후보:** 현재 용량 설정으로 실제 선택 규칙을 적용했을 때 들어갈 ID와 토큰 추정치다. 임베딩 순위 외에 최근 기억 우선 등의 영향도 받는다. Risu 대화 용량을 알 수 없으면 이 항목만 미확인으로 둔다.
- **누적 비교:** 두 모델이 동일한 후보 전체를 정상적으로 검색하고 세 방식의 상위 결과를 전부 평가한 기록만 평균에 포함한다. 같은 모델·주소·검색 설정·용량·상위 개수끼리 묶는다. 모델별 유사도 값과 RRF 값을 서로 직접 비교하지 않는다.

평가 결과는 검색 효율을 보여주며 RP 답변의 일관성이나 객관적 진실을 검증한 수치는 아니다. 모델이나 후보에 따라 이득뿐 아니라 필요 기억이 순위 밖으로 밀려나는 손해도 표시한다.

## 수동 비교 기록과 취소

이 채팅의 최근 24회 / 8MiB를 기기 저장소에 보관한다. 검색 문장, 후보 본문 표시용 일부, 순위, 실제 호출 통계, 직접 표시한 평가와 설정 식별값이 포함된다. API 키, 인증 URL, 벡터는 저장하지 않는다. 표시용 기억 본문은 12,000자까지이며 검색에는 전문을 사용한다. 내보내기에는 검색 문장과 기억 본문 일부가 포함됨을 화면에 안내한다.

측정 창을 닫거나 취소하면 해당 비교의 요청만 중단한다. 일반 채팅 검색은 함께 취소하지 않는다. 기억·원문·채팅·연결 설정 변경을 확인하며, 기록 쓰기에는 저장소 순서 보호를 적용한다. 기억 모두 삭제에는 비교 기록도 포함된다. 이전 기록을 편집하는 늦은 콜백은 삭제된 기록을 되살리지 않는다.

사용자 지시에 따라 개발 중 테스트·실제 API 호출·설치된 Risu 실행·GitHub 게시를 하지 않았다. 실험용 설치 파일만 빌드한다.
