# NyoruMemory

RisuAI의 대화를 **내용·대사 / 사실 / 관계 / 줄거리**로 정리하고, 다음 답변에 필요한 기억을 찾아 넣는 장기기억 플러그인입니다.

**현재 배포 버전: 0.28.0**

## 다운로드 및 설치

**[NyoruMemory.js 다운로드](https://raw.githubusercontent.com/hyo0076/NyoruMemory/main/NyoruMemory.js)**

1. 위 링크의 파일을 `NyoruMemory.js`로 저장합니다.
2. RisuAI의 플러그인 설정에서 파일을 불러옵니다. API 3.0 플러그인을 지원하는 RisuAI가 필요합니다.
3. 채팅 입력창 오른쪽 삼선 메뉴에서 **뇨루기억**을 엽니다.
4. **모델 및 설정**에서 사용할 API와 모델을 연결합니다.
5. RisuAI 프롬프트의 장기기억 항목을 **순수 프롬프트**로 변경하고, 아래 내용을 넣습니다.

```text
[NyoruMemory.memory]
```

기억 정리용 모델은 이 플러그인에서 직접 설정합니다. RisuAI의 메인·보조 모델이나 Provider Manager를 가져오지 않습니다. Gemini의 Vertex AI는 **서비스 계정 JSON**으로도 연결할 수 있습니다. [Vertex AI 설정 안내](Vertex-AI.md)

## 업데이트

0.25.1부터 GitHub 업데이트 주소가 포함됩니다. 이전 버전 사용자는 이번 파일을 한 번 직접 설치하세요. 이후에는 RisuAI의 플러그인 업데이트 확인 기능으로 새 버전을 받을 수 있습니다.

```js
//@display-name NyoruMemory v0.28.0
//@version 0.28.0
//@update-url https://raw.githubusercontent.com/hyo0076/NyoruMemory/main/NyoruMemory.js
```

기존 기억·설정과의 호환을 위해 내부 식별자는 `longmemory`를 유지합니다. 이전 `[LongMemory.memory]` 슬롯도 호환됩니다.

## 주요 기능

- **이중 임베딩**: Voyage 일반·문맥, OpenAI 호환, Google Gemini, Cohere v2 형식을 연결하고, 두 모델의 검색 순위를 합칠 수 있습니다. [설정 안내](docs/dual-embeddings.md)
- **연결 확인·자동 비교**: 임베딩·Jev 연결 확인과 플레이 중 검색 비교 기록을 제공합니다. [임베딩 비교 안내](docs/embedding-comparison.md)
- **Jev 관찰·효과 비교**: 실제 주입과 별도로 가상 선택을 평가하고 요청·응답·사용량을 보관합니다. 선택 기능으로, 새 설치에서는 꺼져 있습니다. [사용법과 한계](docs/jev-memory-shadow.md)
- **병렬 처리·계속 기억하기**: 종류별 추출을 병렬로 진행하며, 전체 기억하기에서 개별 청크가 실패해도 다음 구간을 진행하고 실패 목록을 남깁니다. 인증·요금·저장소 오류처럼 전체 요청에 영향을 주는 경우는 중단합니다. [진행 방식](docs/parallel-bulk-processing.md)

- 내용과 대사를 함께 보관하고, 사실·관계·줄거리를 구분해 관리합니다.
- 저장된 기억을 검색해 프롬프트에 주입하며, 별도로 연결한 임베딩 모델을 사용할 수 있습니다.
- 로어북으로 관계도를 만들고, 대화로 기억을 검수하거나 항목별로 수정·삭제할 수 있습니다.
- 사실과 관계는 사용을 끄면 추출·갱신·검색·주입을 중지하고 기존 기록을 보관합니다.
- 기억 백업과 복원을 지원합니다. 업데이트 전에는 중요한 기억을 백업해 두세요.

## 변경 내용

**0.28.0** — 현재 개발 소스 전체를 설치 파일 하나로 통합했습니다. 0.27.3을 예전 공개판에서 만들면서 누락됐던 이중 임베딩·Voyage 문맥 연결·Jev 관찰 및 자동 비교·병렬 처리·원문 변경 확인·복구 개선을 포함하며, Copilot 연결 수정도 유지합니다. 저장 형식 **1–12**를 읽어 개발본의 기억을 이어 사용합니다. **테스트와 실제 AI 호출은 실행하지 않았습니다.** Jev의 실제 답변 연결과 효과는 아직 확인되지 않았습니다.

0.27.3에서 **“지원하지 않는 저장 버전”**이 떴다면 형식 12의 기억을 형식 11까지만 읽는 배포본으로 열었기 때문일 수 있습니다. 기억을 삭제하거나 재구축하지 말고 위 설치 파일을 업데이트하세요. 내부 저장 키와 기존 기록을 유지합니다.

로컬 최신 파일은 `release/NyoruMemory.js`로 모았습니다. 현재 소스의 포함 모듈·저장 형식·파일 해시는 [배포 구성 명세](release-manifest.json)에 기록됩니다.

**0.27.3** — GitHub Copilot 공식 API 주소에 연결할 때 `Copilot-Integration-Id: vscode-chat`과 클라이언트 호환 헤더를 자동으로 보냅니다. Gemini·Claude의 출력 한도 필드를 `max_tokens`로 맞췄습니다. 모델 요청이 거절되면 요청 모델과 전송·응답 연결 ID를 표시합니다. 추가 HTTP 헤더를 직접 지정했다면 그 설정이 우선합니다. 공개 0.27.2에 이번 연결 수정만 적용했으며 로컬 Jev 관찰 실험은 포함하지 않았습니다. **사용자 요청으로 테스트와 실제 AI 호출 없이 빌드·배포했습니다.**

**0.27.2** — 병렬 작업의 상태 갱신이 응답 도착 전의 빈 사본으로 복구 기록을 덮어쓰던 경로를 수정했습니다. API 응답은 수신 즉시 보관하며 원본을 유지합니다. 빈 기록은 진단 자료와 입력 조건이 같은 이전 응답에서도 복구를 시도합니다. 응답을 찾지 못한 경우 빈 편집창을 숨기고 실제 실패 사유를 표시합니다. **사용자 요청으로 테스트 없이 빌드·배포했습니다.**

**0.27.1** — AI 응답의 단순 JSON 문법 오류를 먼저 코드에서 정리합니다. 필요할 때만 오류 주변 최대 3,200자를 AI에 한 번 보내며, 전체 대화·기억은 보내지 않습니다. 복구창에 저장된 응답·오류 위치를 표시하고 빠른 형식 복구와 해당 항목 재요청을 추가했습니다. `tool_calls` 종료 표시의 결과 처리와 정리 중단 알림도 수정했습니다. **사용자 요청으로 테스트 없이 빌드·배포한 수정본입니다.**

**0.27.0** — 실패한 AI 응답과 원문·작업 ID를 복구 초안으로 보관합니다. 처리 기록에서 직접 수정하거나 뉴뉴와 복구안을 적용할 수 있고, 저장 실패 시 입력창을 유지합니다. 조건이 맞는 종류별 성공 결과는 재사용합니다. 선택형 JEV와 인증정보를 가린 진단 내보내기를 추가했습니다. JEV는 기본적으로 꺼져 있습니다.

자동화 테스트 345개와 브라우저 복구·업데이트 검사를 통과했습니다. 실제 설치된 RisuAI 및 유료 AI 연결은 아직 확인하지 않았습니다. 이전 버전에서 보관하지 않은 실패 응답은 복원할 수 없습니다. 업데이트 알림과 변경 내역은 기존 기능을 사용하며, 설치는 사용자가 선택합니다.

**0.26.0** — 설치 후 첫 실행의 변경 내역 안내, 새 공개 버전 알림, 창 하단의 업데이트 내역을 추가했습니다. 자동 확인은 최대 6시간에 한 번이며 끌 수 있습니다. 오프라인에서도 저장된 내역을 표시합니다. 버전 확인에는 AI를 호출하지 않습니다.

**0.25.1** — GitHub 업데이트 주소 추가. 기억 처리 방식과 저장 식별자는 유지합니다.

**0.25.0** — Google Vertex AI 서비스 계정 JSON 연결, 인증 토큰 갱신, 별도 검수 모델의 Vertex 연결을 추가했습니다.
